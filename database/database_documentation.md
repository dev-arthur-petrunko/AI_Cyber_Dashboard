# Документація: База даних проектів

Цей файл описує всі зміни, впроваджені у папці `базаданных/` та у коді проекту для структурованого зберігання записів про загрози, захисту від дублів та інкрементального наповнення бази.

## 1. Структура папки `базаданных/`

Папка містить схемы, правила, таксономію, приклади та реєстр таблиць. Фізична БД (`data/threats.db`) не копіюється сюди (вона у `.gitignore`).

| Директорія | Файли | Призначення |
|------------|-------|-------------|
| `schemas/` | `threat_schema.json`, `phishing_schema.json`, `ddos_schema.json`, `dataset_schema.json` | JSON-схеми нормалізованих записей для кожної таблиці |
| `taxonomy/` | `threat_types.md`, `severity.md`, `regions.md`, `exploit_maturity.md` | Класифікація типів загроз, рівнів небезпеки, регіонів, зрілості експлойту |

## 2. Зміни у коді проекту

### 2.1 `app/db.py` — новa таблиця стану збирання

Додано ORM-модель `CollectorStateORM` (таблиця `collector_states`):
- `source` (primary key) — назва джерела даних
- `last_fetched_at` — останній час успішного збирання для цього джерела
- `updated_at` — час оновлення запису стану

Додано функції:
- `get_last_fetched(db, source)` — отримати останній час збирання джерела
- `update_last_fetched(db, source, fetched_at)` — оновити стан після збирання

Це дозволяє **інкрементальному збору**: кожен запуск pipeline може починатися з останньої успішної дати, а не з абсолютного порогу.

### 2.2 `app/storage/bulk.py` — batch_size для зменшення навантаження

Функція `bulk_upsert` тепер приймає параметр `batch_size` (за замовчуванням `500`). Велика пачка записей ділиться на менші батчі:
- кожен батч — окрема транзакція з власним `commit()`
- зменшується навантаження на БД (особливо віддалену Postgres/Neon)
- утримується захист від дублів (UniqueConstraint на `source + external_id`)

### 2.3 `app/pipeline.py` — інкрементальний збір

Перед кожним колектором отримується `last_fetched_at` з `collector_states`. Записи, старші за цей час (з запасом 1 година), пропускаються. Після успішного збирання джерела оновлюється `last_fetched_at`. Також додано виклик `bulk_upsert(..., batch_size=500)`.

### 2.4 `app/main.py` — розширення вікна часу

Ліміт параметра `days` у `/threats` піднято з `365` на `1095` (3 роки), щоб записи за останні 3 роки попадали у результат.

## 3. Захист від дублів (три рівні)

| Рівень | Механізм | Деталі |
|--------|----------|--------|
| БД | `UniqueConstraint("source", "external_id", name="uq_source_external_id")` на таблиці `threats` | Гарантує унікальність пари джерело+зовнішній ID на рівні БД |
| Програма (пачка) | Внутрішня дедуплікація в `bulk_upsert` | Дублі всередині однієї пачки відсікаються до запису |
| Програма (оновлення) | Upsert замість insert | Існуючі записи оновлюються (`updated`), а не дублюються (`inserted`) |

Додатково:
- `content_hash` (SHA-256) — допоміжний сигнал для межджерелових дублів (не первинний ключ)
- Захист `published` при `is_backfill=True` — технічні імпорти не «омолоджують» записи

## 5. Важные замечания (из анализа)

### 5.1 Инкрементальный сбор и обновления старых записей

Фильтр по `fetched_at` (время сбора) удалён из pipeline. Теперь система полагается на upsert: если источник обновил старую запись (например, пересчитал CVSS в NVD или добавил CVE в CISA KEV), новая версия перезапишет старую. Это безопаснее, чем фильтрация по дате.

### 5.2 Проверка защиты от дублей

Проверка «повторный запуск: inserted 0» не доказывает защиту от дублей сама по себе (фильтр мог просто пропустить записи). Честный тест: `UniqueConstraint(source, external_id)` проверен напрямую — попытка вставить дубль вызывает `IntegrityError`. Constraint работает на уровне БД.

### 5.3 NULL в external_id

Добавлен `nullable=False` к колонке `external_id` в `ThreatORM` и миграция `0004_collector_states`. Теперь БД отклонит запись с NULL external_id, а не создаст скрытый дубль.

### 5.4 Миграция для collector_states

Создана миграция `0004_collector_states.py` (head: `0004_collector_states`), которая создаёт таблицу `collector_states` и добавляет NOT NULL к `threats.external_id`. На SQLite таблица создаётся автоматически через `init_db()` (create_all), на PostgreSQL/Neon — через Alembic.

### 5.5 73 колекторы, но 8 записей в collector_states

Не все колекторы успешно завершаются (Playwright-колекторы SSU/SSSCIP падают без браузера, некоторые источники недоступны). `update_last_fetched` вызывается только после успешного `bulk_upsert`. Колекторы, которые упали с ошибкой, не обновляют состояние. Это нормальная поведение — состояние сохраняется только для успешных сборов.

### 5.6 Часовые пояса

Все даты хранятся в UTC (наївний datetime без tzinfo). `now_utc()` возвращает `datetime.now(timezone.utc).replace(tzinfo=None)`. Поля `published`, `fetched_at`, `captured_at` — все в UTC. AI-анализ генерируется в 09:00 Europe/Kyiv (UTC+2/+3). Запас 1 час в инкрементальном сборе учитывает разницу в часовых поясах.

### 5.7 .env и секреты

Файл `.env` находится в `.gitignore` (строки `.env`, `.env.local`). Файл `.env` не потрапив у git історію (проверено через `git log --all --full-history -- .env`). Ключи (GROQ_API_KEY, CLOUDFLARE_RADAR_API_TOKEN и др.) не коммитятся. Значения ключей не змінюються — только комментарии могут быть добавлены.
