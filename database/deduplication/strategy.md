# Стратегия защиты от дублей

Документ формализует, как проект Cyber Sentinel гарантирует отсутствие дублирующихся записей угроз в базе данных.

## Первичный ключ дедупликации

| Уровень | Ключ | Где применяется |
|---------|------|-----------------|
| БД (констрейнт) | `(source, external_id)` | `UniqueConstraint("source", "external_id", name="uq_source_external_id")` на таблице `threats` |
| Приложение (пачка) | `(source, external_id)` | `app/storage/bulk.py` — внутри одной пачки отсекаются дубли перед записью |
| Фишинг | `(source, external_id)` | `app/storage/phishing_storage.py` |

Правило: одна пара `(source, external_id)` = одна строка в таблице. Повторный сбор того же источника с тем же `external_id` **обновляет** существующую строку, не создаёт новую.

## Дополнительный ключ (опциональный)

`content_hash` — SHA-256 нормализованного контента (title + url + cve_id). Предназначен для **меж-источниковой** дедупликации, когда один инцидент приходит из разных источников под разными `external_id`.

- Не является первичным ключом.
- Используется только как дополнительный сигнал при поиске похожих записей.
- Не объединяет записи автоматически — требует ручного или правил-based подтверждения.

## Защита внутри пачки (bulk_upsert)

В `app/storage/bulk.py`:

1. Перед записью пачка фильтруется: записи без `external_id` отбрасываются (`skipped_invalid`).
2. Внутри пачки дубли по `(source, external_id)` отсекаются (`skipped_duplicates`).
3. Загружаются все потенциально существующие строки одним запросом (`IN` по source и external_id).
4. Для каждой записи: если существует — обновляются поля; если нет — вставляется новая.
5. Один `commit()` на всю пачку.

## Правила обновления (мерж) существующей записи

| Поле | Поведение при upsert |
|------|---------------------|
| `external_id`, `source` | Ключи — не меняются |
| `title`, `type`, `severity`, `country`, `region`, `vendor`, `products`, `cvss_score`, `epss_score`, `exploit_maturity`, `tags`, `summary`, `url`, `cve_id`, `poc_published`, `added_to_kev` | Перезаписываются новыми значениями |
| `fetched_at` | Всегда устанавливается в текущее время импорта (операционная метаданные) |
| `published` | Перезаписывается, **кроме** случая `is_backfill=True` у новой записи — тогда сохраняется старая дата, чтобы не «омолодить» запись и не создать ложный всплеск метрик `new_cve_24h` |
| `is_backfill` | Устанавливается в `True`, если хотя бы одна из записей (старая или новая) помечена как backfill |

## Почему не удаляются дубли

- Приложение не запускает процедуру массового удаления дублей. Констрейнт БД гарантирует уникальность на уровне записи.
- Если при миграции или импорте обнаружены дубли по `(source, external_id)`, они устраняются на уровне данных до применения констрейнта.

## Таблицы без upsert

| Таблица | Логика | Обоснование |
|---------|--------|-------------|
| `ddos_snapshots` | Каждый запуск добавляет новый срез без upsert | Временные срезы для истории, сравнения «за_now» vs «неделю назад» |
| `dataset_snapshots` | Каждый запуск добавляет новый срез без upsert | История `last_checked` и доступности |
